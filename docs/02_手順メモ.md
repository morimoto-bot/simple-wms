## 2. GASをデプロイする（所要10分）

1. 上のスクリプトエディタのURLを開く（私用のGoogleアカウントで）
2. **合言葉を決めて登録**: 左の歯車「プロジェクトの設定」→ 下の「スクリプト プロパティ」→「スクリプト プロパティを追加」
   - プロパティ: `APP_TOKEN`　値: **16文字以上**の長いランダムな文字列（短いとアプリは動きません。英数字24文字以上を推奨。パスワード管理アプリで生成すると安全）
   - この値はコードやNotionには書かない。iPhoneの設定画面にだけ入れる
3. **権限の承認**: エディタ上部の関数選択で `setupSheets` を選び「実行」→「権限を確認」→ 私用アカウントを選ぶ。「このアプリは Google で確認されていません」と出たら「詳細」→「簡易WMS（GAS倉庫）（安全ではないページ）に移動」→「許可」（自分で作ったスクリプトのため。求める権限はスプレッドシートの操作だけ）
4. **デプロイ**: 右上「デプロイ」→「新しいデプロイ」→ 種類の歯車で「ウェブアプリ」
   - 説明: `v0.3`
   - **次のユーザーとして実行: 自分**
   - **アクセスできるユーザー: 全員**（iPhoneから匿名でfetchするために必要。合言葉を知らない人は何もできない作りです）
   - 「デプロイ」→ 表示される **ウェブアプリのURL（末尾が `/exec`）** をコピー
5. 動作確認: ブラウザで `（コピーしたURL）?action=ping` を開く → `{"ok":true,"app":"simple-wms",…}` と出ればOK
6. コードを直したあと: 「デプロイ」→「デプロイを管理」→ 鉛筆 →「バージョン: 新バージョン」→「デプロイ」（URLは変わりません）。`/dev` のURLは使わない

claspで更新する場合（Claude Codeに頼む場合）: `clasp push` のあと、上の手順6で新バージョンをデプロイします。


### 2-x. GASの更新（v0.5以降）
コード（`Code.gs`）が新しくなった時は、GASエディタに最新の `Code.gs` を入れ（clasp経由なら反映済み）、「デプロイ」→「デプロイを管理」→ 鉛筆（編集）→ バージョン「**新しいバージョン**」→「デプロイ」で更新します（**URLは変わりません**。合言葉も変わりません）。v0.5.1で、シート「商品対応表」の名前が「対応表」に変わりました（古い名前のシートがあれば、デプロイ後の最初の通信で、中身を残したまま名前だけ変わります）。v0.5.0の更新で、出荷伝票シートの右に「作業グループ」「作業開始日時」の見出しが自動で足されます。更新しないと、出荷作業の開始・ピッキングは動きません（それ以外は従来どおり動きます）。

## 3. 画面（index.html）をHTTPSで置く

iPhoneのカメラは **https:// のページでしか動きません**（MDN。localhost以外のhttpでは不可）。GASの画面機能（HtmlService）では動きません（これが前回の失敗の原因）。次のどれかに `index.html` を置きます。

**公開済み（2026-11-06）**: GitHub Pages に置きました。リポジトリ https://github.com/morimoto-bot/simple-wms ／ 画面 https://morimoto-bot.github.io/simple-wms/ 。HTTPSで `index.html` が配信されること（HTTP 200）までは確認済みです。**iPhoneで開いてカメラが動くかは未確認**です。公開リポジトリなので、中身（合言葉・ID・GASのURL・個人情報）に秘密を入れないでください。

| 方法 | 手順の概要 | 向き不向き |
|---|---|---|
| A. GitHub Pages | 新しいリポジトリに `index.html` を入れ、Settings → Pages で公開 | 更新が楽。リポジトリは公開（Public）になる |
| B. Netlify Drop | https://app.netlify.com/drop に `index.html` を入れたフォルダをドラッグ | 一番簡単。URLが自動で決まる |
| C. Cloudflare Pages | Pages で「Direct Upload」にフォルダをアップロード | 無料で安定 |

- ページの中身に **秘密情報は入っていません**（GASのURLと合言葉は、iPhoneの設定画面に入れた値が端末内に保存されるだけ）。ただし画面のコードは誰でも見られる状態になります
- どの方法でも、公開後のURLが `https://…/` で始まること、`index.html` が開くことを確認してください（各サービスの画面は変わることがあるので、公式ドキュメントを見てください）
- 公開URLを他人に教えない限り、第三者がアクセスする理由はありませんが、URLを知っていても **GASの合言葉が無ければ在庫は見られず、変更もできません**

## 4. iPhoneの初期設定

### 4-1. GASのURLと合言葉を入れる
- **既定は手入力**: 右上の ⚙ →「GAS WebアプリのURL」と「合言葉」を貼り付ける（メモアプリ・パスワード管理アプリからコピー）
- 便宜（**自分専用の端末だけ**）: `https://（画面のURL）/index.html#gas=（GASの/exec URLをURLエンコードしたもの）&token=（合言葉）` で開くと入力済みになり、アドレスバーからは消えます。ただし**合言葉がリンクに入る**ので、このリンクをメッセージ・SNS・スクリーンショット・ブックマークの共有に載せないでください（合言葉つきで開くと警告が出ます）。**配布する場合はこの方式を使わない**
- ⚙ の「接続テスト(GET)」と「接続テスト(POST)」を押して、**両方OK**になることを確認

### 4-2. 商品マスタ（サンプル）を入れる
1. ⚙ → 「商品マスタの取り込み」の欄に貼り付けるか、「ファイルを選ぶ」でCSVを選ぶ（Excelで保存したShift_JISのCSVも読めます）
2. 書式: 1行1商品 **`JAN,商品名[,価格[,現在庫[,ロケーション[,SKU]]]]`**（SKUは「対応表」に入ります。複数は ` | ` 区切り）（カンマ／タブ区切り。先頭の見出し行は自動で除外）。ひな形: `sample-master.csv`
3. 「取り込む」→ 追加・更新・スキップの件数が出ます。スキップの行は理由つきで表示されます（チェックデジット不正、桁数違い、商品名なし、重複）
4. 既に登録済みの商品は、名前・価格・ロケーション・SKUを更新します。**在庫は取り込みでは変わりません**。新規で現在庫を付けた場合は、入出荷履歴に「入荷／初期登録」が残ります

### 4-3. ホーム画面に追加（PWA）
1. Safariで画面のURLを開く
2. 共有ボタン →「ホーム画面に追加」
3. iOS 26以降は、ダイアログに **「Webアプリとして開く」** のスイッチが出ます（報道による。WebKitの一次情報は未確認）。オン＝ホーム画面アプリとして開く／オフ＝ブックマーク扱い（Safariで開く）。**両方の状態でカメラが動くか確認してください**
4. ホーム画面のアイコンから開く。初めてカメラを使う時に許可を求められたら「許可」

## 5. 使い方（要点）

画面上部のタブは **入荷／検品／出荷／出庫／棚移動／棚卸／在庫／管理** の8つ（横にスクロールできます）。共通: 「カメラ開始」でスキャン。読めない時はJANの手入力か「写真から読む」。マスタにないJANは、その場で登録フォーム（商品名・価格・ロケーション・SKU）が開きます。

| タブ | 流れ |
|---|---|
| 入荷（予定を消し込む） | 「＋入荷予定を作る」で予定名と明細（`SKUまたはJAN,予定数`）を登録 → 予定を選び、届いた商品をスキャンして**検品済数**を数える（ロケは行ごとに変更。「📷 読む」でロケのバーコードを読んでもよい）→ 途中でやめる時は「途中保存」（状態＝検品中。在庫は動かない。別の端末からも続けられる）→ 「計上して確定」で確認画面（在庫 n→m、残）→ 確定で在庫に加算。足りない分は状態「一部入荷」で残り、次回は同じ予定から続けます。もう来ない分は「予定を閉じる（消込）」、入荷がまだ無い予定は「キャンセル」。超過・予定外も計上できます（履歴メモに残る） |
| 入荷（予定なし） | 「予定なし（現物）」タブ。スキャン → 数量・ロケ → 確認画面 → 確定 |
| 検品（出荷検品＋送り状検品） | 「＋伝票を取り込む」で、CSV（`伝票番号, SKUまたはJAN, 数量`）を貼る／ファイルを選ぶ（氏名・住所などの列があっても保存しません）。1伝票を手入力で作ることもできます。**送り状番号**は、伝票ごとの「送り状」ボタンで入力／「📷 読む」、または配送業者のソフトが出す追跡番号CSV（`受注コード, 送り状番号[, 配送業者]`）の取り込みで伝票に記録します。伝票を選ぶ（「📷 伝票番号を読む」でも開始）→ 商品をスキャンして検品済数を数える → 送り状番号がある伝票は、荷物に貼った**送り状のバーコードを読む**（「送り状検品」欄が「一致」になる）。途中保存すると「検品中」。**商品が全数一致し、送り状が一致すると「検品済みにする」を押せます**。**在庫は動きません**。検品済みのあとに送り状番号を変えると、検品をやり直しになります |
| **出荷作業（まとめて出荷。v0.5）** | 検品タブの「出荷待ち」で、まとめて出荷する伝票にチェック（「全部選ぶ」あり）→ 必要ならグループ名を入れて「**出荷作業を開始**」→ 「出荷作業中：グループ名」の枠ができる。枠の「📋 **ピッキング（リスト）**」で、グループ内の全伝票の商品を**合計数・ロケーション順**に表示（紙は出さない）。バーコードを読むか＋−で数え、必要数で✔ → 「ピッキング完了」→ 各伝票を「検品開始」で検品 → 「出荷」タブで出荷。作業中の伝票はキャンセルできません。やめる時は枠の「出荷待ちに戻す」。**作業を始めなくても、1件ずつ検品・出荷はできます**。ピッキングの進み具合はこの端末だけに残ります |
| 検品（リスト照合のみ） | 貼り付けた予定リスト（`JAN,予定数`）に対して数えて照合し、検品履歴に残します（簡易入力）。在庫は動きません |
| 出荷 | 「検品済」の伝票を選ぶ（送り状番号も表示）→ 明細ごとの在庫 n→m（不足は赤）→ 「出荷を確定」→ 確認 → 明細の数量分だけ在庫が減り、状態が「出荷済」になります |
| 出庫 | 伝票に紐づかない払い出し。スキャン → 数量 → **理由（必須）** → 確認 → 確定。履歴は区分「出庫」、メモ「理由:…」 |
| 棚移動 | スキャン → 移動先のロケーションを入力（または「📷 読む」）→ 確認 → 確定。在庫数は変わらず、ロケだけが変わります |
| 棚卸 | ①開始（棚卸名・範囲・未カウント品の扱い）→ ②実在庫入力（スキャン／＋−／直接入力）→ ③差異プレビューで確定。「中止」で入力を破棄できます（在庫は変わりません） |
| 在庫 | 検索・ロケ絞り込み・並び替え。行をタップで商品名・価格・ロケーション・SKUを編集（在庫数は編集不可） |
| 管理 | 入荷予定・出荷伝票の一覧（状態で絞り込み、行をタップで明細）、在庫の検索、入出荷履歴の検索（区分・キーワード）、**CSVダウンロード**（商品マスタ／在庫一覧／入出荷履歴／入荷予定／出荷伝票）。パソコンのブラウザで開くと画面が広く表示されます |
| **送り状CSV（v0.6。管理タブ）** | ECサイト・受注管理から出した**注文CSV**（どのサービスのものでも可。1行目は見出し行）を、ファイルで選ぶか貼り付け →「振り分けてCSVを作る」。CSVの列は自動で当てはめ、**「列の割り当て」**で直せる（注文番号は必須。次回から覚える）。**配送方法**で、ヤマト（B2）・佐川（e飛伝III）・日本郵便（ゆうプリR）・クリックポストに分かれ、出力先ごとの取り込みCSVをダウンロードできる。初回は「設定」で、発送元（名前・郵便番号・住所・電話）と、配送方法の振り分け（`キーワード,出力先` を1行ずつ）を入れる。配送方法の列が無いCSVは、「どれにも合わない注文の出力先」で1社にまとめる。宛先は**画面の中だけ**で扱い、保存・送信しない（使い終わったら「データを消す」）。発行は各社のソフトで行い、できた番号は検品タブの「送り状番号を取り込む」で戻す |

### SKUとJAN（対応表）
- ECのSKUは、スプレッドシートの「対応表」に `SKU, JAN` で持ちます。1つのJANに複数のSKUを付けられます。商品の編集画面の「SKU」欄（複数は ` | ` 区切り）か、マスタ取り込みの6列目で登録できます
- 入荷予定・伝票を作る時、コードはまずSKUとして探し、見つからなければJANとして探します
- **解決できないコード**があると、その伝票（予定）は作られず、画面に未解決のコードが出ます。JANを入れて（または📷で読んで）「紐づけ」を押し、もう一度「CSVを取り込む」を押してください。取り込み済みの伝票は無視されるので、何度押しても二重にはなりません

### 状態（ステータス）
- 入荷予定: 入荷待ち → 検品中（途中保存）→ 一部入荷（計上して残りがある）→ 完了（全数入荷または消込）／キャンセル
- 出荷伝票: 未検品 → 検品中（途中保存）→ 検品済（商品が全数一致、送り状番号があれば送り状も一致）→ 出荷済／キャンセル

### 運用上の注意
- **棚卸中は、入荷・出荷・出庫・棚移動など他の在庫操作を止めてください**（確定時の帳簿在庫は、確定した瞬間のマスタの値のため）。この端末で棚卸中の間は、他のタブに警告が出ますが、操作は止まりません
- 予定名・伝票番号は重複できません。キャンセルした番号も再利用できません
- **スプレッドシートの行は、手で書き換えないでください**（状態は明細から計算して保存しています）。直したい時はアプリから操作します
- バーコードは画面の枠の中に**横向き**で入れてください（縦向きは写真から読む）
- 同じバーコードをかざし続けても1回しか数えません。次の1個は、いったんカメラから外してから（約1秒）かざしてください
- iPhoneは**バイブ非対応**（Safariの仕様）。音と読み上げ、枠の緑の点滅で知らせます
- 検品・棚卸・入荷の途中経過は、この端末にも保存されます（画面を閉じても続きから再開できます）。検品中・入荷検品中の分はサーバーにも保存できます（「途中保存」）
- 行が増えると読み込みが重くなります。数千行を超えたら、完了した予定・出荷済の伝票を別のスプレッドシートへ退避してください（将来の課題）

### 補足: Bluetoothスキャナ（実機課題の逃げ道・v0.4.2で対応）
カメラ読み取りで実機課題（暗所・小さいJAN・連続スキャンの速さ）が出る場合は、**Bluetoothの2Dバーコードスキャナ（HIDキーボードモード）**をiPhoneにつなぎます。スキャナは「キーボード入力」として読んだ数字を送り、最後にEnterを送ります。
1. スキャナを「キーボード（HID）」モードにし、**読み取り後にEnter（CR/LF）を送る**設定にして、iPhoneとBluetooth接続する
2. ⚙設定の「スキャナ（キーボード入力）モード」をオンにする
3. 画面下のJAN入力欄（「スキャナで読み取り（入力待ち）」）を一度タップする。以後は読み取るたびに処理される（画面のキーボードは出ない）
4. ロケーション・伝票番号・送り状番号の読み取りボタン（📷 読む）を押すと、カメラは開かず、そのままスキャナで読む
- 確認済み: PCブラウザで、キー入力（数字＋Enter）によるJAN読み取り・連続読み取り・ロケーションの読み取り待ち。**実際のスキャナ・iPhoneは未確認**（チェックリスト #30）
- 制限: Enterを送らない機種は動かない。入力欄のフォーカスが外れると受けられない（ほかの入力欄を使っている間は、そのままその欄に入る。終わると元に戻る）

### うまくいかない時
- **カメラが映らない／真っ黒**: ⚙ →「カメラ診断」を実行して結果を控える。「HTTPS等: いいえ」→ URLが https:// か確認。「カメラ許可: denied」→ 設定アプリ → Safari →「カメラ」を「確認」か「許可」に。ホーム画面アプリだけ動かない場合は、一度Safariのブラウザ表示で許可してから開き直す。それでも動かない場合は、診断結果を私に見せてください
- **接続テストがNG**: 「JSONを返しませんでした」→ URLが `/exec` か、デプロイが「全員」か確認。「合言葉が違います」→ スクリプトプロパティ `APP_TOKEN` と同じか確認。GETはOKでPOSTだけNG → CORSの問題の可能性。その場合は私に伝えてください（書き込みの送り方を変える対応を入れます）
- **在庫が合わない**: スプレッドシートの「入出荷履歴」を確認（処理後の在庫数が並ぶので、どこでずれたか追えます）。管理タブの「履歴」からも検索できます

実装上の限界（テストで確認した範囲）:
- ZXingは、1モジュール2〜5pxのEAN-13を、画素ごとの独立ノイズ±30（明暗の差210のうち）まで19〜20/20で読めた。±40ではほぼ読めなくなる（極端に暗くノイズが多い画像の想定）
- バーコードが映っていないフレームの処理は、ノイズが多いと1フレーム100〜200ms（PCでの計測。iPhoneでは未計測）。読み取りは約100msおきに試み、重い画像ではコマ数が減る
- 縦向きのバーコードは、カメラ読み取りでは読めない（写真から読むでは読める）
- 送り状のバーコード（ITF／Codabar／Code 128 など）: 読み取りの設定には入れてあるが、**実際の送り状での読み取りは未確認**。読めない種類があれば、手入力（送り状の欄に番号を入れる）で代用できる
- ロケ・伝票番号の読み取り（Code 128／Code 39／QR）: **Code 39 は生成した画像で復号を確認**。Code 128 と QR はZXing-jsの対応形式として設定しているが、画像での確認はしていない（**未確認**）
- 伝票・入荷予定の「ヘッダ＋明細」の設計は、LOGILESS Developers の入荷予定伝票（`inbound_delivery`。ヘッダのstatus・明細のquantity／received_quantity）を参考にした。状態の遷移はAPI本文に書かれていないため、この手順メモの「状態」の表は自分たちで決めたもの（https://app2.logiless.com/developer/documents/interface/inbound_delivery）
- ZXing-jsはCDN（jsdelivr）から読み込みます。電波が無い場所では起動しません（オフライン非対応）

## 9. セキュリティ（必ず読む）

このアプリのGASは「自分として実行／全員（匿名を含む）」で公開されるため、**`/exec` のURLを知っている人は誰でもアクセスできます**。実質の防御は**合言葉（`APP_TOKEN`）だけ**です。

### 9-1. 合言葉とURLの扱い
- 合言葉は**16文字以上**（短いとアプリが動きません）。長いランダムな文字列にする
- **URLと合言葉は別々に保管**する。SNS・スクリーンショット・公開リポジトリ・Notion・ドキュメントに書かない
- 合言葉をコードやHTMLに埋め込まない（このアプリのHTMLに秘密は入っていません）。端末の設定画面と、GASのスクリプトプロパティだけに置く
- 画面のURLに `#gas=…&token=…` を付けて渡す方式は、合言葉がリンクに残るので、**配布では使わない**（手入力が既定）

### 9-2. 合言葉が漏れたかもしれない時（再発行の手順）
1. GASのスクリプトエディタ →「プロジェクトの設定」→「スクリプト プロパティ」で、`APP_TOKEN` の値を**新しい長い文字列**に変更して保存
2. 「デプロイ」→「デプロイを管理」→ 鉛筆 →「バージョン: 新バージョン」→「デプロイ」（URLも念のため作り直すなら「新しいデプロイ」。古いデプロイは「アーカイブ」）
3. iPhone・PCの⚙で、合言葉（URLを変えたらURLも）を更新
4. スプレッドシートの「入出荷履歴」を見て、身に覚えのない操作が無いか確認する（履歴は追記のみで、全操作が残ります）

### 9-3. チェックリスト（デプロイ前と配布前）
- [ ] デプロイの設定: 「次のユーザーとして実行」=**自分**、「アクセスできるユーザー」=全員（匿名を含む）。**これ以外の人にスプレッドシートの編集権限を渡していない**
- [ ] スプレッドシートの共有設定が「制限付き」（**リンクを知っている全員にしない**）。所有者（利用者本人）のみ
- [ ] `APP_TOKEN` が16文字以上で、他のサービスのパスワードと使い回していない
- [ ] 合言葉つきのリンクを誰にも送っていない
- [ ] `Code.gs` の `SPREADSHEET_ID` は、自分の環境で使う場合だけ入れる（**配布するコードでは空にして**、利用者が自分のIDを入れる）。共通の合言葉を配らない
- [ ] 氏名・住所などの個人情報を、このアプリに取り込んでいない（伝票CSVに入っていても保存しない設計。**宛先データをどう扱うかは、設計メモ12-12の残論点**）

### 9-4. 入力まわりの安全
- 商品名・メモ・理由などが `=` `+` `@` で始まっても、シートでは文字列として保存され、数式にはなりません（Excelで開くCSVも、先頭に `'` を付けて無害化します）
- メモや理由に改行があっても、1つの空白にして保存します（行が壊れません）
